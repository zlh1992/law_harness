# 法务助手客户演示脚本

## 演示边界

以下案例均为虚构案例。它们用于展示风险分流、行动清单、记忆和决策溯源，不构成法律意见。公共界面不要输入身份证号、完整合同、商业秘密或未脱敏个人信息。

## 1. 成立、用工与隐私的综合体检

输入：

```text
演示案例（完全虚构）：上海 SaaS 公司本月招聘首名员工并收集注册邮箱。请用不超过 350 字给出 7/30/90 天风险分流和本地依据；加载成立体检、用工、数据合规与来源索引技能。必须先写入 Semantica 溯源并在最后给出 trace_id。
```

预期路由：`startup-foundation-compliance-audit`、`workforce-classification-and-labour-contract`、`cross-jurisdiction-privacy-router`、`law-wiki-source-index`。

可展示效果：按 P0/P1/P2 给出 7/30/90 天动作；答案列出本地依据；末尾出现 `决策溯源：lawtrace-...`。已验收的一次演示产生了 4 个来源节点、Semantica decision ID、答案 SHA-256 与 PROV 完整性校验值。

## 2. 员工还是独立承包人

输入：

```text
（虚构）上海 SaaS 公司让产品经理按日打卡、按月固定报酬、使用公司设备，却准备签“独立承包人协议”。请识别事实、分级风险、立即补救和需核验的本地依据；先完成 Semantica 溯源。
```

预期路由：`workforce-classification-and-labour-contract` + `law-wiki-source-index`。

可展示效果：不会根据合同标题直接下结论，而会要求核对管理控制、考勤、报酬、工具、持续性与岗位属性，并把劳动、税务、工伤与外包责任列为律师复核项。

## 3. 面向欧盟用户的 AI 产品隐私路线

输入：

```text
（虚构）中国公司向欧盟用户提供 AI 会议纪要，收集邮箱、音频转写，并调用第三方模型。请列上线前、首月、季度的 30/60/90 合规路径和资料缺口；引用本地来源边界并写入 Semantica。
```

预期路由：`cross-jurisdiction-privacy-router` + `law-wiki-source-index`。

可展示效果：先追问主体地域、数据类型、跨境和供应商处理方式，再按 CN / US / EU 区分告知、同意、供应商条款、处理记录、事件响应等待核验事项；不会虚构实时法规或给出合同级定稿。

## 4. 跨会话的本地记忆

第一回合输入：

```text
请记住（演示、无敏感信息）：星桥科技是中国 SaaS 种子轮，当前优先事项是员工用工与隐私上线。只确认保存成功即可。
```

第二回合在新会话输入：

```text
请回忆星桥科技的已保存演示偏好，并据此只列本周两项法务优先级。必须使用本地记忆工具，不要猜测。
```

预期路由：第一回合 `mcp__memory__remember_fact`，第二回合 `mcp__memory__recall`。已验收：第二个新会话从本机 SQLite 返回一条 `local_only: true` 的演示记忆；除非用户明确说“记住”或“回忆”，预设不会调用记忆工具。

## Semantica 溯源怎么看

```text
问题
  ├─ 匹配的法务 skill
  ├─ 本地 Wiki 来源索引
  └─ Semantica decision
       ├─ trace_id（展示在回答末尾）
       ├─ decision_id
       ├─ 来源节点与 supported_by 边
       ├─ answer_sha256
       └─ PROV integrity checksum
```

在答案出现 trace ID 后输入：

```text
请查询并展示决策溯源：<回答末尾的 trace_id>
```

助手会调用 `mcp__semantica__get_legal_trace`，返回该答复的来源、置信度、不确定性、答案哈希和完整性校验结果。审计文件仅在本机 `.data/semantica/` 内保存。
