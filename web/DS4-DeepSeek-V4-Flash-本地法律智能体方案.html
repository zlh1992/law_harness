EXECUTIVE VERDICT

结论：能部署，但要按“单用户、低并发、受控长上下文”来设计

技术可行 · 建议进入 PoC

DS4（DwarfStar）是针对 DeepSeek‑V4‑Flash 的原生 Metal 推理引擎。其硬件指南将 Q2 imatrix 明确列为 96–128GB Mac 的推荐量化；128GB 机器可同时容纳约 81GB 权重和一段实用 KV 缓存。

上线首期固定在 100k 上下文、并发 1。官方模型支持 1M 上下文，不代表 128GB 本地量化也应直接开到 1M；长上下文会显著增加内存和首字延迟。

01

API 完整

DS4 提供 OpenAI Chat Completions、Responses、流式输出及工具调用接口。

02

局域网可共享

在 DS4 前加入自建网关，Windows 只需 OpenAI 兼容的 baseURL 和 Token。

!

不是企业级高并发

DS4 与 Harness 均处快速迭代期，适合作为专用工作站，不宜承诺 HA 或多人高 QPS。

IMPLEMENTATION BLUEPRINT

从模型到界面：三条配置链

1

Mac：运行 DS4

下载 Q2 imatrix，DS4 只监听 127.0.0.1；先以 100k 上下文和 8GB 磁盘 KV 缓存启动。

2

Mac：加固 API

网关监听 :4011，签发局域网 TLS，生成高强度 Token，限制 Windows IP 与并发。

3

Windows：接入 Harness

Harness 使用 OpenAI 兼容 provider；模型 baseURL 指向 Mac 网关，API key 从环境变量读取。

MAC · TERMINAL
xcode-select --install
git clone https://github.com/antirez/ds4.git
cd ds4
./download_model.sh ds4f-q2
make

# DS4 只绑定回环；不直接暴露给局域网
./ds4-server -m ./ds4flash.gguf \
  --ctx 100000 \
  --kv-disk-dir "$HOME/Library/Caches/ds4-kv" \
  --kv-disk-space-mb 8192 \
  --host 127.0.0.1
WINDOWS · CORDIS.YML
llm-pi-ai:
  providers:
    openai:
      baseURL: https://mac-llm.local:4011/v1
      apiKeyEnv: DS4_GATEWAY_TOKEN
      models:
        - id: deepseek-v4-flash
          name: DeepSeek V4 Flash · Local DS4
          contextWindow: 100000
          maxTokens: 32768

agent-default-model:
  provider: openai
  model: deepseek-v4-flash
  reasoningEffort: medium
钥

这里的 API key 不应再是 dummy

DS4 本身不校验密钥；网关必须生成真实、随机、可轮换的 Bearer Token。Harness 里的 DS4_GATEWAY_TOKEN 仅引用环境变量，不把密钥写入 YAML。自签名证书需安装到 Windows 信任库。

MEMORY DECISION

为什么选 MCP Local Memory，而不是等待 Harness 原生记忆

适配路径短Harness 已有官方 MCP 客户端，Node 22 与 npx 启动方式一致。

数据可带走单一 SQLite 文件，本地备份、导出、纠错和遗忘都容易审计。

法律风险可控ARCHIVIST_STRATEGY=passive，只在明确指令或审批后写入。

WINDOWS · MEMORY MCP
- id: mcp-legal-memory
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: legal_memory
    transport: stdio
    command: npx
    args: ['-y', '@beledarian/mcp-local-memory@2']
    env:
      MEMORY_DB_PATH: !!js process.env.LEGAL_MEMORY_DB
      ARCHIVIST_STRATEGY: passive

LEGAL WORKFLOWS

它能完成哪些法律相关工作？

定位是“可追溯、能记住、会用工具的法律工作助手”，不是自动执业律师。

01

合同审阅与条款比对

抽取义务、期限、责任与例外；与模板库比较，输出风险矩阵和修改建议。

02

法律检索与研究备忘录

合并内部权威资料与公开网络研究，生成带来源、时间和冲突提示的初稿。

03

案件时间线与证据索引

从文书、邮件和附件中识别人物、事件、日期，形成可回溯原文的时间线。

04

尽调与批量文件归纳

按预设清单识别缺失材料、异常条款、关联主体和待核事项。

05

文书起草与双语摘要

基于所内模板生成律师函、研究提纲、会议纪要和中英摘要初稿。

06

事项连续记忆

跨会话记住已确认事实、客户别名、写作偏好和下一步，但每次可查看、纠正或删除。

WHY THIS STACK

+ 核心优势

  • ✓核心生成本地化，降低合同与案件材料外发风险
  • ✓一次硬件投入后，不再按模型 Token 计费
  • ✓Windows 旧设备复用；界面、知识和研究工具模块化
  • ✓知识与记忆严格分层，引用、来源和变更可审计
  • ✓OpenAI 兼容 API，可继续接入其他内部应用

△ 已知约束

  • Q2 量化会牺牲一部分精度，应以真实法律任务做验收。
  • DS4 与 DeepSeek Harness 都在快速迭代，需固定版本并留升级回滚方案。
  • 笔记本不是高可用服务器；睡眠、断电、散热均影响服务。
  • 单用户低并发为宜；100k 以上长上下文需按任务评估。
  • MiroFlow 联网检索会访问外部站点，查询必须先脱敏。
